# Changelog — 2026-09-01

## Phase 3 — the panel (`v0.2`)

- **Status:** ✅ Completed (reviewed)
- **Scope:** panel / QML views · branch `main`
- **Summary:** clicking the bar mark now opens a panel with Sites, Services, Environment and —
  only when there is something to say — Needs attention, in a dense list or three columns.

### Changes

- `Panel.qml` — `Panel` + `KeyboardPanel` + `PanelKeyCatcher`, header (mark, name, version,
  update badge, view toggle), a `Flickable` body and the two hand-offs. View toggle bound to
  `v`, refresh to `r`, choice persisted through `bar.shell.updateEntryInline()` into
  `shell.json` (`{"id":"io.hubdev.buddy","view":…}`), so it survives a shell restart.
- Sections as their own components — `SitesSection`, `ServicesSection`, `EnvironmentSection`,
  `AttentionSection`, `ExtrasSection` — so `DenseView` and `ColumnsView` **compose** the same
  five rather than each restating them. Leaves: `StatusDot`, `Section`, `InfoRow`, `SiteRow`,
  `ServiceRow`, `CollapseRow`.
- `Model.js` — all the panel's logic, QML-free and tested: `siteGroups()`, `serviceGroups()`,
  `envRows()`, `checkById()`, `checksSummary()`, `versionLabel()`, and `env.flags` built from
  `health.checks`.
- `Theme.js` — `ICONS`/`icon()` (codepoints reused from lerd Glance, so they are known to
  resolve in this font), `DRIVER_GLYPHS`/`driverGlyph()`, `serviceLevel()`, `siteLevel()`.
- `BarWidget.qml` — panel `Loader` with property injection (`summary` **bound**, not assigned,
  or the panel freezes on whatever was true when it opened); `open`/`close`/`toggle` IPC routes,
  broadcast to every monitor; click refreshes then toggles.
- Body scrolls, capped at 75% of the available screen height — this machine has 15 sites where
  lerd Glance assumes 1. Parked sites and never-configured services collapse behind a count.

### Findings

- **No new CLI was needed.** Every section comes from the Phase 1 contract as shipped,
  including Node's version, which arrives as the `nodejs` health check rather than a field of
  its own. The only thing lerd Glance has that HubDev cannot supply is its CPU/memory meter
  strip: there is no CPU figure at all, and the memory figure costs a `docker stats` sample per
  service (~1 s in the daemon), which is not a price a 30-second poll should pay. §5.2's
  Environment column is now a measured decision rather than an argued one.
- **`caddy-down.json` described a document the CLI cannot emit.** It set `route_present: false`
  on all 15 sites; the shipped Go *omits* the field when Caddy is down, so one stopped Caddy is
  reported once instead of fifteen times. First time "fixtures are the contract" cost a fixture
  rather than a code change.
- **…which exposed a real hole in the model.** With the field absent, `routePresent` correctly
  reads as *unknown, not a fault* — and the panel then drew fifteen **emerald** sites under a
  red Caddy row. Sites now carry `serving` (active **and** routed **and** Caddy up) beside
  `routePresent`: the first decides the dot, the second decides whether to raise an issue. No
  test would have caught it — none asks what colour a row is.
- **The value elides, not the label** (`InfoRow`), and `versionLabel()` stops `latest` becoming
  `vlatest`.
- **`qs.Ui`'s panel machinery is available to third-party plugins** — `Panel`, `KeyboardPanel`,
  `PanelKeyCatcher`, `PanelSectionHeader`, `PanelSeparator`, `PanelActionButton`, `Button` are
  all exported in `/usr/share/omarchy/shell/Ui/qmldir` and work from `~/.config/omarchy/plugins`.
  R1 asked again about a different import, answered the same way — by doing it.

### Verification

- `npm test` — 72 passing (was 53).
- `omarchy plugin validate` — exit 0.
- On screen in three states: healthy live environment (columns and dense), and the
  `caddy-down` fixture driven through the live widget via a read-only shim, showing
  *"Needs attention · Caddy is stopped — no site will resolve"* with every site row red.

## Panel review pass — Environment order, wording, and clickable sites

- **Status:** ✅ Completed (reviewed)
- **Scope:** panel / QML views · branch `main`
- **Summary:** three changes from reading the panel as a user rather than as its author —
  reorder Environment, cut the doctor's wording down to a panel row, and make a site a link.

### Changes

- **Environment reordered** to Caddy → DNS → Hosts File → PHP → Docker → Node.js →
  Diagnostics. DNS and the hosts file were below Docker, where they read as trivia; they belong
  under Caddy because the three are one question asked three ways — *will a URL resolve at
  all*. `ENV_CHECK_IDS` became `ENV_CHECKS` with an `after` key, so placement is data with a
  test on it rather than the incidental order of two loops.
- **Promoted checks re-worded for the panel.** `DNS (.test)` → `DNS`, and *"Port 80 listening,
  .test domains should resolve"* → *"Port 80 listening"*. The tail only restated the dot beside
  it; the TLD was wrong as well as long — this machine serves `.test`, `.lab` and `.craft`.
  **The value override applies only while the check is green:** a failing check's detail is the
  *reason*, and the stand-in beside a red dot would be a lie. The label override always applies —
  a name does not depend on state.
- **Site rows are links.** Clicking one opens it in the desktop's browser; hover underlines the
  domain and sets the pointer cursor. `Model.siteUrl()` picks the scheme from the site's own
  `tls` (this machine has some of each) and **validates the domain as a plain hostname** before
  it reaches a command line — anything else returns `""` and the row simply does not respond.
  `BarWidget.openUrl()` runs `Util.execArgv(["omarchy-launch-browser", url])`: fixed argv handed
  to bash as positional parameters, so untrusted data can never be re-tokenised, and detached,
  so nothing in the shell waits on a browser.
- The row **raises a signal** (`SiteRow.activated` → `SitesSection.siteActivated` → the view →
  `Panel.openSite`) rather than launching anything. `BarWidget.qml` stays the only file that
  does I/O — the chain exists so that invariant survives Phase 4 adding real actions.
- Docs: `docs/implementation-plan.md` (Phase 3 → "What the first review of the panel changed"),
  `README.md`, `CLAUDE.md` — the last records that site-open already ships, so Phase 4 does not
  re-implement it, and that `Util.execArgv` is the right primitive for detached actions and the
  wrong one for anything whose exit code matters.

## Redact client identities from the fixtures

- **Status:** ✅ Completed (reviewed) — **history rewrite still outstanding**
- **Scope:** `test/fixtures/` · branch `main` · commit `bfd367b`
- **Summary:** the fixtures were captured from this machine and carried fifteen real client
  names, domains and absolute paths; they now carry neutral stand-ins that preserve every
  property the tests rest on.

### Changes

- All 15 sites remapped across the 8 fixtures that have a `sites` section — `name`, `domain`
  and `path` — plus the real home directory → `/home/dev` everywhere, including the `disk_usage` check.
- `hubdev` and `terminal-radio` kept: the user's own projects, not a client's.
- `test/model.test.mjs` and `test/source.test.mjs` — the three places a real domain was written
  into an assertion or a comment.
- `docs/implementation-plan.md` — the two the two absolute local paths
  became `~`-relative, which reads better anyway.

### What the mapping had to preserve

The fixtures are the contract, so a redaction that changed their *shape* would have quietly
weakened the suite rather than just anonymising it:

| property | before | after |
|---|---|---|
| sites / active | 15 / 14, parked at index 4 | same |
| TLD spread | `.lab` ×8, `.test` ×6, `.craft` ×1 | same |
| drivers | 14 laravel, 1 generic | same |
| index 0's alphabetical rank among active | 11 of 14 | 11 of 14 |
| path shapes | varied, one not `<client>/<app>` | same |

The TLD spread and the rank are the two that are genuinely load-bearing. The spread is what
makes *"a row labelled `(.test)` names one of three"* true — a review decision and a lesson rest
on it. The rank keeps *"an unrouted site sorts above every healthy one"* meaningful: had the
stand-in for index 0 sorted first alphabetically, that test would still pass, for the wrong
reason, forever.

## A guard, so this is a one-off rather than a habit

- **Status:** ✅ Completed (reviewed) · commit `d6c210a`
- **Scope:** `tools/privacy-scan.mjs`, `test/privacy.test.mjs`, `.githooks/pre-commit`

### What it checks

A real home directory (fixtures use `/home/dev`), the client-work folder name, a secret-shaped
key with a real-looking value, a PEM private key block, and a denylist of client project names.

**The denylist is hashed, and that is the whole design.** A scanner carrying client names in
plaintext would be the leak it exists to prevent, and the first file anyone greps. Tokens hash
to 16 hex chars; a hit reports *that* something forbidden is present, never what — so the
report is safe to paste anywhere. The plaintext mapping stays in the gitignored
`redaction-map.py`, and a test reads it **when present** to prove the hashes really cover the
names that were removed, rather than trusting the generator. On a clean clone that test skips
instead of pretending to cover what it cannot see.

Wired into `npm test` (so any CI running the suite gates on it), `npm run privacy`, and
`.githooks/pre-commit` — `git config core.hooksPath .githooks` per clone.

### Three defects in the guard, all found by running it rather than reading it

- **The denylist shipped empty.** The generator's output was interpolated inside an *unquoted*
  heredoc, so the shell expanded `${hashes}` away before the writer ran. Every other rule
  worked, the suite was green, and the one rule that mattered most matched nothing. Found only
  by feeding it a known-bad line.
- **The scanner matched its own client-folder literal** — it would have failed the
  whole-tree scan the moment it became a tracked file. The pattern is now assembled from
  fragments, because a scanner that cannot be scanned needs a permanent special case, and the
  special case is what eventually lets something real through.
- **The first self-test contained real client names as its "must catch" samples,** and the
  pre-commit hook rejected the commit. That is the most useful thing the guard has done so far:
  it caught a genuine leak, written by the person writing the guard, on its first run. Samples
  are now a synthetic canary or assembled at runtime — and the canary is assembled too, since
  spelling it out would fail the same scan.

### Verification

- 82 tests passing (was 78). `npm run privacy` clean over 45 tracked files.
  `omarchy plugin validate` exit 0.
- Every rule proven to fire on a planted violation, and every legitimate shape proven to stay
  quiet — including `Never emits a secret: services carry no \`password\``, which is prose, and
  `password: "hunter2-SHOULD-NOT-APPEAR"`, which is the R6 canary.

## Phase 4a — the three detached site actions

- **Status:** ✅ Completed (reviewed on screen)
- **Scope:** panel actions · `io.hubdev.buddy` · branch `main`
- **Summary:** Hovering a site row reveals a terminal in the project, the project in the file
  manager and the project in the editor — the three Phase 4 verbs that need none of Phase 4's
  machinery.

### Why these three, and why now

The plan's §5.3 puts actions on the row they belong to, revealed on hover, **in place of the
detail they cover** — lerd's rule. These three are the ones that could ship without the rest
of the phase: all detached, no output anyone reads, nothing destructive, no chance of a sudo
prompt. There is no exit code to report and nothing to wait on, so no `actionState`, no
spinner, no guard timer and no confirm gate. `Util.execArgv` is the primitive, exactly as it
already was for `openUrl`.

**HubDev already owned all three** — `site:terminal`, `site:folder` and `site:edit` — so no CLI
work was needed. Each resolves *the user's* default rather than naming a program: the terminal
from `$TERMINAL`, the file manager via `xdg-open`, the editor via `omarchy-launch-editor`. Same
reasoning that makes the browser action `omarchy-launch-browser` rather than a hardcoded
Chromium.

### Changes

- **`Actions.js`** (new) — the allowlist and the argv construction. `siteActions()` is the list
  the row renders; `siteArgv(summary, site, key)` returns the exact argv or `[]`. `[]` is the
  refusal, and it is the only failure mode: an unknown verb, a site the current snapshot no
  longer lists, or a name that cannot go on a command line.
- **`SiteRow.qml`** — a `HoverHandler` (not a `MouseArea`: the action buttons sit on top and
  would steal the row's hover the instant the pointer reached for them, making the buttons
  vanish under the cursor). The trailing block reserves the width of the *wider* of its two
  states, so the domain elides at the same point hovered or not, and the row height is set by
  the buttons whether or not they show — otherwise the whole list jumps as the pointer crosses.
- **`Panel.qml`** — `runSiteAction(site, key)`: validate in tested JS, hand a fixed argv to the
  one file that spawns, close the panel. It closes for the same reason `openSite` does — a
  terminal or an editor is about to take the screen, and a popout left hanging behind it reads
  as a click that did not land.
- **`Theme.js`** — three glyphs, checked against this machine's JetBrainsMono Nerd Font cmap
  rather than a cheatsheet, because a missing glyph is a tofu box that only shows up on
  somebody else's screen.

### The refusals are the point

`hubdev` parses its own flags out of the argv it is handed, so a site named `--print` must
never become one. `Actions.js` validates the name against the snapshot *and* against a shape
that cannot be re-read as a flag, and node tests every refusal alongside every accepted shape.
The QML knows which key it sent and nothing else; **`BarWidget.qml` is still the only file that
spawns.**

### Verification

- 99 tests (was 82), 17 of them new in `test/actions.test.mjs` — every row shape → the exact
  argv, plus each refusal.
- `omarchy plugin validate` exit 0 · `qmllint -I /usr/share/omarchy/shell` clean ·
  `npm run privacy` clean.
- All three actions exercised on screen against the live snapshot, and the disabled state
  confirmed on a site the snapshot does not list.

### Files

- `Actions.js` — new; the allowlist, the argv, the refusals
- `test/actions.test.mjs` — new
- `SiteRow.qml` — hover, the trailing block, the three buttons
- `Panel.qml` `DenseView.qml` `ColumnsView.qml` `SitesSection.qml` — the signal chain

## Type-to-filter — the panel filters as you type

- **Status:** ✅ Completed (reviewed on screen)
- **Scope:** panel search · `io.hubdev.buddy` · branch `main`
- **Summary:** Any printable key narrows Sites and Services to what matches, marking the
  matched characters — no field to click into and no shortcut to remember, because the panel
  already holds the keyboard the moment it opens.

### The shape

The first character raises a slim box under the header showing what was typed and `n of m`;
the two searchable sections narrow, the other three step aside, and the matched characters are
marked in the accent colour. `Enter` opens the top match. `Esc` clears the filter and **only
then** closes the panel — otherwise the key for undoing a narrowing throws the whole panel
away. An empty query is indistinguishable from never having searched: zero height, zero cost.

Parked sites and not-set-up services are searched too. That is the best moment the feature has
— the collapsed row is exactly what was hiding the thing being looked for.

### The bound is the whole feature

The match is a subsequence — `cpa` finds `clinic-portal-app.test` the way a launcher would —
but a **bounded** one. The unbounded version shipped first and failed within a minute of real
use: a three-letter query returned the intended site *and* an unrelated one whose letters
happened to fall in that order across three different words. The user's report was simply "I
don't know why that second entry is showing", which is the correct reaction and the whole
argument. So:

- the first character may land anywhere;
- every character after it must **continue a run or begin a word** (`-`, `.`, `_`, `/`);
- **every** occurrence of the first character is tried as an anchor, best score wins — greedy
  commits to the wrong one and then reports *no match at all*, which is worse than a false
  positive because the user is certain the thing is there.

The first character stays free so `dev` still finds `hubdev.test`.

### Two costs, both deliberate

- **`KeyCatcher.qml` duplicates `qs.Ui`'s `PanelKeyCatcher`** — the only file in this plugin
  that duplicates something the shell ships, and the reason is at the top of the file. The
  shared component spends the unmodified letters on a row cursor (`h`/`j`/`k`/`l`/`x`), which
  is four of the letters in `hubdev.test`, and this panel never had that cursor. There is no
  configuration of it that yields both. What the fork keeps: `Keys.BeforeItem`, Escape, Tab,
  and the `blocked` seam. What it drops: only what was never used.
- **`v` and `r` became `Alt+V` and `Alt+R`.** A panel that filters on `v` cannot also toggle
  its layout on it, and a reserved letter silently eats the first keystroke of any query
  starting with it — a bug that works during testing and fails for whoever's project starts
  with `v`.

It is deliberately **not** a `TextField`: there is no field to focus, no cursor to place and no
click target, so every key that edits the query is handled in one place instead of juggling
active focus against the key router for features a filter does not need.

### Two bugs found on screen, neither visible to the test suite

- **A binding loop in the caret.** Anchored to `text.left + text.contentWidth` while the text's
  `right` was anchored to `caret.left`. Qt resolved it by pinning the caret to the far left and
  logging one line nobody reads. The caret is now positioned with a computed `x:`.
- **`Array.isArray` is FALSE for a JS array that has round-tripped through a QML `property var`.**
  Spans were computed in `Model.js`, stored on a `property var`, and handed back in to be
  rendered — and that round trip turns a real Array into a `QVariantList` wrapper which
  indexes and has `.length` but is **not** an Array. `highlightHtml`'s guard fell through to
  plain text. Under `node --test` both sides are real Arrays, so all 19 span assertions passed
  while every label on screen drew plain: the feature was *silently half-shipped*. Anything
  crossing back out of QML is now duck-typed, and the regression test uses a deliberately
  non-Array stand-in. **This is the one blind spot in "keep the logic in plain JS so node can
  test it", and it is always this boundary.**
