# Changelog — 2026-08-31

## Draft implementation plan for the HubDev Omarchy Quattro plugin
- **Status:** ✅ Completed (reviewed)
- **Scope:** planning / research · branch `main`
- **Summary:** Researched `lerd Glance`, the Omarchy Quattro plugin spec and the HubDev CLI, then drafted a phased implementation plan for `io.hubdev.buddy` and put it through an adversarial review that changed seven of its decisions.

### Changes
- Repository initialised as a planning repo — no plugin code yet, by design: Omarchy Quattro is not installed on this machine (still 3.8.5, no QuickShell, no `omarchy plugin`).
- `docs/implementation-plan.md` — full plan: reference decomposition, the HubDev/lerd gap, transport decision, JSON contract, product scope, seven phases, eight risks, the grill.
- `docs/research/hubdev-buddy-plan.html` — presentation copy, published as a private Artifact, built on HubDev's own brand palette found in `readme-drafts/`.
- `README.md` — states the planning status up front and names the one unknown the plan hangs on.

### Findings that shaped the plan
- HubDev has **no local HTTP API and no machine-readable CLI** — `--json` is silently ignored and ANSI is emitted even under `NO_COLOR`. lerd Glance's whole transport assumption does not hold here.
- `mcp.Bridge` (`devhub-go/internal/mcp/server.go`) already exposes every read the widget needs as JSON-tagged structs, so `hubdev snapshot --json` is one new `cli_snapshot.go`, not a feature. Phase 1 revised from ≈3–4 sessions to ≈1–2.
- `RunDiagnostics()` already returns `{Name, Status, Message, Detail, Icon}` — the panel's environment-health block comes free.
- **No file locking exists anywhere in `devhub-go`** (in-process `sync.RWMutex` only), which answers the concurrency question for polling reads and replaces it with a smaller pre-existing one: writes are last-writer-wins between the widget, the CLI and the GUI.
- The only `ListenAndServe` in the tree is the DNS stub, so a loopback daemon is genuinely greenfield and correctly deferred to Phase 6.

### Verification
- All findings read directly from source or measured on this machine against HubDev v1.27.0: CLI latency (`site:list` 59 ms · `service:list` 87 ms · `status` 374 ms), `NO_COLOR` behaviour, absent listening sockets (`ss -ltnp`), config state files, and the `mcp.Bridge` interface.
- Plan self-reviewed under an adversarial pass; 13 challenges recorded with verdicts, 7 folded back into the plan body.
- Artifact HTML validated for tag balance before publishing.
